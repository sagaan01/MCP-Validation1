Name the participants

Learn to label Host, Client, and Server in real setups — the skill every later MCP lesson builds on.

Why this matters for the mission

Debugging Cursor MCP configs fails fast when “server” is used for everything. Official architecture draws three distinct roles. Your win today: point at a concrete product setup and name each role correctly.

Primary source Read Architecture overview → Participants (official MCP docs). This lesson compresses that section; the docs are the source of truth.

Knowledge (short)

MCP uses a client–server architecture. An MCP Host — an AI application like Cursor, Claude Desktop, or Visual Studio Code — connects to one or more MCP Servers by creating one MCP Client per server.

  • Host — coordinates clients; owns the user-facing AI app.
  • Client — maintains the connection to exactly one server and fetches context for the host.
  • Server — the program that provides context (tools, resources, prompts), whether local or remote.

Local servers often use stdio on the same machine. Remote servers often use Streamable HTTP and may serve many clients. “MCP server” names the program, not its location. Cite: architecture docs.
